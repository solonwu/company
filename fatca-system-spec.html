FATCA 申報系統規格書

台灣金融機構依美國 FATCA（Foreign Account Tax Compliance Act）規定，向 IRS IDES 系統申報美籍應申報帳戶的內部系統。 涵蓋帳戶資料查詢、GIIN／金鑰／Metadata XML 維護、XML 產製、CMS 數位簽章與 AES/RSA 加密打包、IDES ZIP 送出與回覆解密。

01

系統概述

系統採前後端分離：Angular 18 前端 + Spring Boot 3.3.5 多模組後端。核心申報流程從查詢帳戶資料開始， 組出符合 FATCA XML v2.0.1 Schema 的申報文件，經 CMS 數位簽章、AES-256-CBC 加密、RSA 加密 Session Key 後， 打包成 IDES 規範的 ZIP 檔，供人工上傳至 IRS IDES 系統；另提供 IDES 回覆通知檔（.p7m）的解密預覽功能。

Angular 18 前端fatca-frontend
↓ HTTP Basic Auth（admin/admin123）
Spring Boot APIfatca-api :8080
↓
XML 產製fatca-xml
簽章／加密fatca-crypto
共用 Entity／Repofatca-core
↓
PostgreSQL（開發）DatabaseProfileAutoSelector 自動偵測

開發環境的資料庫自動偵測機制（DatabaseProfileAutoSelector）會先嘗試連線正式環境 SQL Server， 3 秒逾時後自動切換為本機 PostgreSQL，可用 DB_PROFILE 環境變數強制指定。完整啟動與環境設定步驟見 repo 內 STARTUP_GUIDE.md，本文件聚焦架構與功能規格，不重複部署細節。

後端模組結構

Maven 多模組專案，fatca-backend/pom.xml 為父 POM。fatca-batch／fatca-ingestion 兩模組已於 2026-07-09 確認無前端串接後移除。

模組用途狀態
fatca-core共用 JPA Entity、Repository、Enum、Value Object（GIIN／Money／TIN）部分使用中
fatca-xmlFATCA XML v2.0.1 建構（FatcaXmlBuilder）與 XSD 驗證部分使用中
fatca-cryptoIDES 簽章／加密／解密（CMS SignedData、AES-256-CBC、RSA、金鑰與 GIIN 管理服務）使用中
fatca-apiSpring Boot 主模組，REST API、安全性設定、資料庫自動偵測部分使用中
fatca-classifyW-9/W-8BEN 帳戶分類邏輯孤立
fatca-submissionIDES SFTP 上傳與通知解析孤立

「部分使用中」表示模組內同時存在正式串接的程式碼與孤立、無人呼叫的舊架構程式碼，詳見 §6、§7。

04

前端功能規格

共 8 個功能頁面，皆需 HTTP Basic 登入（預設 admin / admin123，對應 API_USER／API_PASSWORD 環境變數）。

🏠Dashboard/dashboard

總覽首頁：各機構類型目前啟用的 GIIN、待申報銀行／信託帳戶筆數、最近一次申報狀態、IRS 憑證到期提醒（≤30 天警示／過期標示）。

API
GET /giin · GET /accounts/bank · GET /accounts/trust · GET /fatca/submissions · GET /keystore
🔑GIIN 管理/giin

GIIN 設定 CRUD。每個機構類型（BANK/TRUST/BRANCH）須有一筆 active 記錄，供申報與 XML 產製時查詢使用。

API
GET/POST /giin · PUT/DELETE /giin/{'{'}id{'}'}
🔐金鑰管理/keystore

上傳／檢視 SENDER_P12（自己的私鑰）、IRS_CERT（IRS 公鑰憑證）、BRANCH_CERT（分行稅務局憑證，選用）。顯示各類型最新啟用金鑰與到期倒數。

API
GET /keystore · POST /keystore/sender-p12｜irs-cert｜branch-cert · DELETE /keystore/{'{'}id{'}'}
📝Metadata XML 管理/metadata-xml

維護各機構類型專屬的 Sender GIIN Metadata XML（IDES 規定）。產生任何申報 ZIP 前必須先上傳，缺少時系統會 fail-fast 拒絕產生。

API
GET /metadata-xml · POST /metadata-xml/{'{'}fiType{'}'} · DELETE /metadata-xml/{'{'}id{'}'}
📋申報管理/report

Tab 1：查詢申報明細＋產生 IDES 申報 ZIP（查 XML_* 舊表組出 XML，僅支援銀行部）。Tab 2：申報記錄列表，可依年度篩選、下載歷史 ZIP。

API
POST /fatca/report/preview · POST /fatca/report/from-sp · GET /fatca/submissions · GET /fatca/download/*
📊帳戶查詢/accounts

銀行／信託／分行帳戶分頁列表，7 欄皆可點欄名排序。信託／分行資料來源表尚未確認，目前固定回傳空分頁。

API
GET /accounts/bank｜trust｜branch（支援 sortField／sortOrder）
📩解密回覆/decrypt

上傳 IDES 回覆通知檔（.p7m）與私鑰密碼，解密並預覽／下載明文 XML 內容。

API
POST /fatca/decrypt
🔒手動簽章加密/sign-encrypt

已有現成 XML 時，可上傳／貼入內容直接觸發簽章加密，或勾選產生 Nil Report（無應申報帳戶年度）；不經資料庫查詢。

API
POST /fatca/manual-sign-encrypt · POST /fatca/nil-report

XML_* 舊申報暫存表

對應 ASP.NET 系統 STP_toXML 預存程序原本讀取的資料表；本機 Postgres 版本僅供開發測試，正式環境讀取真實 SQL Server 表。帳戶查詢畫面與新版 Java XML 產製邏輯皆直接查這 7 張表。

資料表用途
XML_DocSpec文件索引；nodeident 標示 ReportingFI（IV/IVa2）／帳戶申報（IVb）／PoolReport（IVc）
XML_CorrectableOrganisationParty_TypeReportingFI 本身（機構名稱、地址、GIIN）
XML_CorrectableAccountReport_Type帳戶申報主檔：帳號、isOrg、餘額、幣別
XML_CorrectableAccountReport_Payment帳戶所得明細（選用，IRS 官方 PaymentType 代碼 FATCA501-506）
XML_OrganisationParty_Type法人帳戶持有人
XML_PersonParty_Type自然人帳戶持有人
XML_PoolReportPool Report／Nil Report 摘要

已知限制與技術債

信託部／分行帳戶查詢固定回傳空結果
LegacyAccountQueryService.findTrustPage／findBranchPage 目前寫死回傳空分頁。XML_* 表沒有部門欄位可辨識歸屬，資料來源表尚待確認。
待確認資料來源
申報 XML 產製僅支援銀行部
SptXmlService 已改為 Java 查表組 XML（不再呼叫 STP_toXML SP），但呼叫 fiType=TRUST 會直接拋出 IllegalStateException，同樣是部門欄位缺失所致，刻意不靜默回傳銀行部資料。
延後開發
V4 Flyway 遷移在 H2 測試環境語法不相容
單一 ALTER TABLE 內串接三個 ADD COLUMN IF NOT EXISTS，真實 Postgres／SQL Server 可執行，H2（MODE=PostgreSQL）會拋語法錯誤，導致 fatca-api 模組所有測試在 Spring Context 啟動階段全部失敗。已知問題，經使用者確認暫不修復。
既有問題
既有測試失敗（與功能無關）
GIINTest／FatcaXmlBuilderTest 因測試 fixture 用了不符 GIIN 正規表達式格式的假資料而失敗；IdesCryptoServiceTest 有 1 個既有斷言不符。皆與本次相關改動無關，已用 git diff 確認未曾改動過這些檔案。
既有問題
第二組孤立架構（本次盤點新發現，尚未處理）
ReportingFI／Account／AccountHolder／FinancialAccount／ReportableAccount／FatcaReport／SubmissionRecord 七個 Entity（皆空表）＋對應的 4 個孤立 Controller（AccountController／ReportController／SubmissionController／FatcaReportController）＋ fatca-classify／fatca-submission 兩個孤立模組＋一個零呼叫的 com.fatca.xml.XmlGeneratorService， 共同構成一組完整可編譯、可執行、但完全沒有前端串接的舊架構世代，與已移除的 fatca-batch／fatca-ingestion 是不同批次的技術債。
孤立，未處理
